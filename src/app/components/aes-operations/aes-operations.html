SubBytes Transformation

Non-linear byte substitution using the S-Box lookup table

How It Works

SubBytes is a non-linear substitution step where each byte in the state is replaced with another according to a fixed 16x16 lookup table called the S-Box.

For a byte value, the upper nibble (4 bits) selects the row and the lower nibble selects the column. The value at that position becomes the output.

Substitution Process
Input: 0x{{ toHex(subBytesInput()) }}
Row: {{ subBytesResult().row.toString(16).toUpperCase() }} (upper nibble)
Column: {{ subBytesResult().col.toString(16).toUpperCase() }} (lower nibble)
Output: 0x{{ toHex(subBytesResult().output) }}

Почему именно такая таблица подстановки?

S-Box в AES — это не случайная таблица. Она математически сконструирована для максимальной криптостойкости. Процесс создания S-Box состоит из двух шагов:

Шаг 1: Мультипликативный обратный в GF(2⁸)

Для каждого байта b вычисляется его обратный элемент b⁻¹ в поле Галуа GF(2⁸), так что b × b⁻¹ = 1. Ноль отображается в ноль (у нуля нет обратного). Это даёт максимальную нелинейность — функция обращения в конечном поле имеет наилучшие характеристики стойкости к дифференциальному и линейному криптоанализу.

Шаг 2: Аффинное преобразование

Результат инверсии пропускается через аффинное (линейное + сдвиг) преобразование над GF(2). Это устраняет фиксированные точки (байты, которые отображались бы сами в себя) и делает S-Box несимметричным. Без аффинного преобразования S-Box имел бы алгебраическую структуру, которую можно было бы использовать для атак.

Почему не случайная таблица?

Случайная таблица может иметь слабые места: линейные приближения, дифференциальные характеристики с высокой вероятностью, фиксированные точки. Математическая конструкция S-Box AES доказуемо обеспечивает:

  • Максимальную нелинейность (112 из 120 возможных)
  • Низкую дифференциальную равномерность (= 4)
  • Отсутствие фиксированных точек (S(x) ≠ x для всех x)
  • Отсутствие обратных фиксированных точек (S(x) ≠ x̄ для всех x)

ShiftRows Transformation

Cyclical byte shifts for inter-column diffusion

How It Works

ShiftRows cyclically shifts the bytes in each row of the state by a certain offset.

Row 0 No shift
Row 1 Shift left by 1
Row 2 Shift left by 2
Row 3 Shift left by 3

Зачем нужен ShiftRows?

Без ShiftRows каждый столбец матрицы шифровался бы независимо от остальных. MixColumns работает внутри одного столбца, SubBytes работает с каждым байтом отдельно. Только ShiftRows перемешивает байты между столбцами.

Вместе ShiftRows и MixColumns обеспечивают полную диффузию за 2 раунда: изменение одного байта входа затрагивает все 16 байт выхода.

Почему именно такие сдвиги (0, 1, 2, 3)?

Сдвиги выбраны так, чтобы каждый байт столбца после ShiftRows попадал в разные столбцы. Если бы все строки сдвигались одинаково — это был бы просто поворот столбцов, не дающий межстолбцовой диффузии.

Значения 0, 1, 2, 3 — единственный набор, при котором 4 байта из одного столбца после сдвига оказываются в 4 разных столбцах. Это максимизирует скорость диффузии и является частью «Wide Trail Strategy» — стратегии проектирования, которую авторы Rijndael использовали для доказуемой стойкости.

MixColumns Transformation

Matrix multiplication in Galois Field GF(28)

How It Works

MixColumns treats each column as a polynomial over GF(28) and multiplies it with a fixed matrix:

[
02030101
01020301
01010203
03010102
]

Почему именно эта матрица?

Матрица MixColumns — это MDS-матрица (Maximum Distance Separable) над GF(2⁸). Это означает, что она обеспечивает максимальную диффузию: если на входе отличается хотя бы один байт, на выходе будут отличаться все четыре байта.

Коэффициенты 01, 02, 03 выбраны не случайно — это самые маленькие ненулевые элементы GF(2⁸), для которых умножение реализуется максимально эффективно:

  • ×01 — тождественная операция (ничего не делать)
  • ×02 — сдвиг влево на 1 бит + условный XOR с 0x1B (если старший бит = 1). Это как умножение на x в полиноме по модулю
  • ×03 — это ×02 XOR ×01, то есть (сдвиг + условный XOR) XOR исходное значение

Почему GF(2⁸), а не обычная арифметика?

В обычной арифметике умножение выходит за пределы байта (255 × 255 = 65025). В GF(2⁸) результат всегда помещается в 1 байт, и каждая операция обратима. Сложение — это XOR (нет переполнений, нет знака), умножение — полиномиальное по модулю неприводимого полинома.

Это делает AES алгебраически элегантным: все операции определены в одном поле, все обратимы, и всё эффективно реализуется в аппаратуре.

AddRoundKey Transformation

XOR the state with the round key derived from the cipher key

How It Works

Each byte of the state is XORed with the corresponding byte of the round key.

XOR Operation
State[i,j] = State[i,j] XOR RoundKey[i,j]

Почему именно XOR?

  • Самообратимость: A XOR B XOR B = A. Это значит, что для расшифровки используется та же операция — AddRoundKey одинаков при шифровании и расшифровании
  • Биективность: XOR не теряет информацию. Для любого ключа K функция f(x) = x XOR K является биекцией (взаимно-однозначным отображением)
  • Скорость: Одна машинная инструкция на процессоре. XOR 128 бит — одна операция на SIMD-регистрах
  • В GF(2⁸) XOR = сложение: XOR — это сложение в поле Галуа GF(2⁸). Поэтому AddRoundKey — это сложение состояния с ключом в алгебраическом смысле

Почему AddRoundKey стоит и первой, и последней?

AES начинается и заканчивается AddRoundKey. Это не случайно: без начального AddRoundKey первый SubBytes был бы одинаковым для всех ключей (от ключа ничего не зависит). А без финального AddRoundKey последний раунд можно было бы «отмотать» без знания ключа. Таким образом, ключевой материал «обрамляет» все раунды, делая шифр стойким даже при атаках на крайние раунды.

Key Expansion (Key Schedule)

Генерация раундовых ключей из исходного 128-битного ключа

Зачем нужно расширение ключа?

AES-128 выполняет 10 раундов шифрования, и в каждом раунде используется свой раундовый ключ. Плюс ещё один ключ для начальной операции AddRoundKey. Итого нужно 11 раундовых ключей (176 байт) из одного 128-битного (16 байт) исходного ключа.

Почему это важно для безопасности?

Расширение ключа гарантирует, что каждый раунд использует уникальный ключевой материал. Это предотвращает атаки, основанные на повторном использовании одного и того же ключа.
