Algorithm Overview

Understanding AES

Advanced Encryption Standard - the symmetric block cipher that secures our digital world.

What is AES?

The Advanced Encryption Standard (AES) is a symmetric block cipher chosen by the U.S. National Institute of Standards and Technology (NIST) in 2001. It replaced the aging DES (Data Encryption Standard) and has become the most widely used encryption algorithm in the world.

AES is based on the Rijndael cipher, designed by Belgian cryptographers Joan Daemen and Vincent Rijmen. The algorithm was selected after a rigorous five-year standardization process that evaluated 15 competing designs.

Symmetric Encryption

AES uses the same key for both encryption and decryption. This differs from asymmetric algorithms like RSA, which use separate public and private keys.

Block Cipher Structure

AES operates on fixed-size blocks of 128 bits (16 bytes). The data is arranged in a 4×4 matrix of bytes called the State. Each byte in the state can be represented as a value from 0 to 255 (0x00 to 0xFF in hexadecimal).

Why exactly 128 bits?

Rijndael (the algorithm behind AES) supported blocks of 128, 192, and 256 bits. NIST chose a fixed 128-bit block size as the optimal trade-off: large enough for security (a birthday attack requires 2⁶⁴ blocks), yet small enough for efficient hardware implementation. The 4×4 byte size maps perfectly onto 128-bit SIMD registers in modern CPUs.

Why are bytes filled by columns, not rows?

This is one of AES's least obvious details. When you take 16 bytes of input, they fill the state matrix column by column (column-major order), not row by row.

Why column-major order?

This is designed so that MixColumns works with the correct data. MixColumns processes each column of the matrix as a polynomial over the Galois field. By filling data column-wise, each column contains 4 consecutive input bytes — and MixColumns mixes precisely those. ShiftRows, on the other hand, shifts rows, mixing data between columns. Together, these two operations provide full diffusion — every output bit depends on all input bits after just a few rounds.

Substitution-Permutation Network (SPN)

AES is built on the Substitution-Permutation Network (SPN) architecture. Each round consists of alternating two types of operations:

  • Substitution: SubBytes replaces each byte via the S-Box. This creates non-linearity — without it, the cipher could be broken by solving a system of linear equations.
  • Permutation: ShiftRows and MixColumns mix bits across positions. This creates diffusion — changing one input bit affects all output bits.
  • Key mixing: AddRoundKey XORs the state with the round key, introducing dependence on the secret.

This architecture was proposed by Claude Shannon in 1949. He proved that alternating "confusion" (obscuring key-ciphertext relationship) and "diffusion" (spreading plaintext influence) are necessary properties of a strong cipher.

Why 10 rounds for AES-128?

The number of rounds was chosen with a large security margin. Rijndael's authors calculated that full diffusion is achieved in just 2 rounds. Resistance to differential and linear cryptanalysis requires ~6 rounds. 10 rounds provide a significant safety margin. Increasing the key to 256 bits requires 14 rounds to compensate for related-key attacks.

Security Properties

AES achieves its security through two fundamental cryptographic properties:

Confusion

Each bit of the ciphertext depends on multiple bits of the key. The S-Box substitution creates complex, non-linear relationships between input and output.

Diffusion

Each bit of plaintext influences many bits of ciphertext. ShiftRows and MixColumns spread changes across the entire state matrix.

Galois Field GF(2⁸) — Mathematical Foundation

All AES operations are defined in the finite Galois field GF(2⁸). This field has 256 elements (matching all possible byte values), with specially defined addition and multiplication:

  • Addition is simply XOR. 0x57 + 0x83 = 0xD4. Addition and subtraction are identical (a + a = 0).
  • Multiplication is polynomial multiplication modulo the irreducible polynomial x⁸ + x⁴ + x³ + x + 1 (= 0x11B). This guarantees the result always fits in a single byte.

Why this specific polynomial? It is irreducible over GF(2) — it cannot be factored. Think of it as a prime number, but for polynomials. Among all irreducible degree-8 polynomials over GF(2), the Rijndael authors chose 0x11B because it yields the most efficient hardware implementation.

In GF(2⁸) every non-zero element has a multiplicative inverse — and this is the key property for constructing the S-Box. The multiplicative inverse of byte b is a byte b⁻¹ such that b × b⁻¹ = 1 in GF(2⁸).

Key Expansion

From a single 128-bit key, AES generates 11 round keys (44 four-byte words = 176 bytes). Each round uses its own round key for the AddRoundKey operation.

The key expansion algorithm is designed so that changing one bit of the original key changes roughly half the bits in every round key — a property known as the avalanche effect.
